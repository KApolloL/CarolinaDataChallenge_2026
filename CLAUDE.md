Apply when working anywhere in this folder (Carolina Data Challenge 2026; project name Carolina HighGround, formerly Blue Ridge FloodWatch; team Kent Lee, Matthew Martin, Aaron Chen, Minh Nguyen; R + Python via Quarto and reticulate). Read README.md first. Vault hub: ~/Documents/KALNotes/Projects/Competitions/CarolinaDataChallenge.

- Goal: find what makes NC storm and flood events deadly or costly, focused on Western NC after Hurricane Helene (11 study counties). Combines NOAA Storm Events with NHD hydrography, terrain, NCDOT structures, NLCD imperviousness, SSURGO soils, and FEMA NRI, then models in Python.
- Layout: `src/` code (top-level `*.qmd` are settings only; `_analysis_body.qmd` holds sections 1-6, `_modeling.qmd` section 7, `_conclusion.qmd`, `_appendix.qmd`; `R/` helpers; `content/` interview quotes and Minh's explorer `highground_explorer.html`). `data/raw/` inputs (read-only), `data/derived/` caches, `data/ml_ready/` Python handoff files. `outs/` generated: `report/`, `figures/`, `tables/`, `presentation/`. `docs/` is the GitHub Pages site (`index.html` + `media/interview.mp4`).
- Run: from the project root, `quarto render src/final_analysis_deliverable.qmd` (final, about 5 min) or `src/analysis_quick.qmd` (about 2 min preview). Params via `-P name:value`. Python section needs conda env `highground` (setup command in README.md).
- Gotcha: the modeling section must set `OMP_NUM_THREADS=1` and `KMP_DUPLICATE_LIB_OK=TRUE` before Python starts, or gradient boosting segfaults (two OpenMP runtimes). Already handled in `_modeling.qmd`; do not remove.
- Gotcha: R strings with non-ASCII symbols (degree sign, ±, ÷) render as `<U+00B0>` in figures and tables. Use ASCII in R code.
- Conventions: edit shared sections in the `_*.qmd` files, not in the settings-only top-level reports. Never modify `data/raw/`. Split by the `split` column, group CV by `episode_id`, never use outcome columns as predictors, keep spatial NAs as missing. `high_consequence` uses a training-years-only threshold (currently $200,000).
- The ML export is skipped with a red warning if a feature group is entirely missing; do not force it with `allow_degraded_export` without checking input paths. Never render an old copy of a qmd from the project root: one did this once and overwrote `data/ml_ready/` with empty features.
- Updating the Pages site without a re-render: re-render the final report, then extract its embedded video into `docs/media/interview.mp4` and save the page as `docs/index.html` (a short Python script; see git history). Pages must publish from `main` / `/docs`.
- Git: big raw data, caches, and rendered HTML in `outs/report/` are git-ignored; GitHub rejects files over 100 MB. Check staged sizes before committing.
- Key results (Oct 21 2026 run, 21 features): best CV model is logistic regression, PR-AUC 0.299 +/- 0.126 vs base rate 0.078 and season-only 0.186. In the feature ladder only rainfall (+0.092) and local flood history (+0.023) clearly add for LR; place helps the RF slightly (+0.024); hydrology and tract SVI add nothing measurable. The holdout is dominated by Helene (66% of test positives); without that week holdout PR-AUC is about 0.08. Report these numbers, not the old "PR-AUC 0.221, 2.8x chance" (judges called that overstated).
